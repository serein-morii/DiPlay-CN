# DiPlay 0.2.19 — 2026-10-12

Public preview for compatible BYD Android head units. Android 7.1+ (API 25) remains the minimum; Android 7.1–8.1 still needs vehicle testing. This update makes wired CarPlay start sooner and on more head units, fixes the audio clock for calls, Siri and navigation prompts, fixes CarPlay restarting or shrinking around the DiLink 4 dashboard map and the reversing camera, adds Japanese and completes Traditional Chinese, and lets a phone download the diagnostic report.

## Highlights

- Wired CarPlay starts several seconds sooner on many head units: each startup step used to wait 2 s for a USB write the iPhone refused. It now also starts on iOS 26 when the iPhone first offers a USB mode without CarPlay, on Android 7.1–9 head units whose firmware removed the USB permission page, and **Auto-confirm USB permission** finds the system dialog. [#644](https://github.com/shihabal3amri/DiPlay/pull/644), [#689](https://github.com/shihabal3amri/DiPlay/pull/689)
- For calls, Siri and navigation prompts in the 16 kHz audio format, DiPlay reported the playback position to the iPhone three times too fast, which can make a call hard to understand. It now counts at the format's own rate. The microphone restarts when its first read after a call starts fails, and music no longer underruns every few seconds while CarPlay is in the background. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- On DiLink 4.0 with the dashboard map on, CarPlay no longer restarts at the first touch after it connects. With the status bar kept on screen, CarPlay no longer stays scaled down after the reversing camera. With **Smooth video** or **Direct video output**, the last picture stays on screen when DiPlay comes back instead of a black screen. [#663](https://github.com/shihabal3amri/DiPlay/pull/663), [#674](https://github.com/shihabal3amri/DiPlay/pull/674), [#669](https://github.com/shihabal3amri/DiPlay/pull/669)
- DiPlay is available in Japanese, Traditional Chinese is complete, and 67 more Arabic strings no longer fall back to English. [#646](https://github.com/shihabal3amri/DiPlay/pull/646), [#691](https://github.com/shihabal3amri/DiPlay/pull/691), [#682](https://github.com/shihabal3amri/DiPlay/pull/682), [#681](https://github.com/shihabal3amri/DiPlay/pull/681), [#631](https://github.com/shihabal3amri/DiPlay/pull/631)
- **Settings → Diagnostics → Get the report on a phone** downloads the diagnostic report on a phone, by QR code or by typing an address and a code. The connection screen shows a tip that fits each failure, asks to turn on Bluetooth when it is off, and wireless CarPlay works on Xiaomi phones with MIUI 13. [#686](https://github.com/shihabal3amri/DiPlay/pull/686), [#687](https://github.com/shihabal3amri/DiPlay/pull/687), [#685](https://github.com/shihabal3amri/DiPlay/pull/685), [#677](https://github.com/shihabal3amri/DiPlay/pull/677), [#679](https://github.com/shihabal3amri/DiPlay/pull/679), [#673](https://github.com/shihabal3amri/DiPlay/pull/673)
- A redesigned settings menu inside CarPlay, an optional album-artwork card on the dashboard map, BYD navigation audio defaults on a first setup, and a report that says why the car hotspot could not be started. [#642](https://github.com/shihabal3amri/DiPlay/pull/642), [#660](https://github.com/shihabal3amri/DiPlay/pull/660), [#656](https://github.com/shihabal3amri/DiPlay/pull/656), [#667](https://github.com/shihabal3amri/DiPlay/pull/667)

## Connection setup and recovery

- Wired CarPlay starts several seconds sooner on many head units. Until CarPlay starts, the iPhone refuses DiPlay's writes on the USB network pipe. Each refused write waited 2 s, and the iPhone's identification and authentication replies waited with it: about 2 s per step in reports from Android 8.1 to 14 head units ([#634](https://github.com/shihabal3amri/DiPlay/issues/634), [#335](https://github.com/shihabal3amri/DiPlay/issues/335), [#301](https://github.com/shihabal3amri/DiPlay/issues/301)). Until the iPhone takes its first network frame, a frame that cannot go out at once is now dropped after 20 ms, as it was after 2 s before. The report records `NCM bulk-out ready after N dropped frames`. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- Wired CarPlay on iOS 26 no longer stays on "Opening CarPlay…" when the iPhone offers a USB configuration with the multiplexer and network interfaces but not CarPlay mode, as on a Proton S70 (ECarX E02) with an iPhone 12 Pro Max ([#634](https://github.com/shihabal3amri/DiPlay/issues/634)). DiPlay now asks for CarPlay mode first, and uses such a configuration only if the iPhone refuses or comes back without CarPlay mode. The report shows `action=request-transition` or `action=reuse-without-apple-ethernet`. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- **Auto-confirm USB permission** now finds the system USB dialog. Android reports that dialog to accessibility services as `android.app.Dialog`, not by its activity name, so the service never acted, even on head units that show the standard dialog ([#409](https://github.com/shihabal3amri/DiPlay/issues/409)). It now also checks system dialogs reported that way and confirms only when the text names DiPlay and a USB device, iPhone or iPad. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- The wheel-key service no longer stays on "Allowed, starting…" after the car closes DiPlay. Android marks the service as crashed and starts it again only once it sees it off the allowed list. DiPlay removed and re-added it too quickly for Android to notice ([#606](https://github.com/shihabal3amri/DiPlay/issues/606)), and now waits a second in between. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- Wireless CarPlay connects on Xiaomi devices with MIUI 13 on Android 12. Their Bluetooth service refused every connection to the iPhone because DiPlay no longer asked for the old Bluetooth permission on Android 12 and newer, which MIUI still checks, as on a Redmi K30 4G ([#671](https://github.com/shihabal3amri/DiPlay/issues/671)). DiPlay now requests it on every Android version; Android grants it without a prompt. Pending acceptance. [#673](https://github.com/shihabal3amri/DiPlay/pull/673)
- Car hotspots that broadcast a second 5 GHz network named after the hotspot with `_5G` can use it: enter that name in the car hotspot details ([#617](https://github.com/shihabal3amri/DiPlay/issues/617)). DiPlay accepts the name, keeps the car hotspot's security and lets the iPhone choose the channel. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)

- Wired CarPlay works on Android 7.1–9 head units whose firmware removed the system USB permission page. DiPlay found the iPhone, but its permission request never got an answer, so the connection stayed on "Requesting iPhone permission". When that page is missing and the car's network ADB is approved, DiPlay grants itself access to the iPhone through ADB, and still asks the usual way if that fails. The report logs `USB permission UI state=…` and `USB permission ADB grant result=…`. Contributed by @ycl2018 ([#689](https://github.com/shihabal3amri/DiPlay/pull/689)).
- With the head unit's Bluetooth switched off, wireless CarPlay asks the driver to turn it on at once, instead of setting up the car hotspot or Wi‑Fi Direct first and failing afterwards on every retry. Contributed by @Boring206 ([#679](https://github.com/shihabal3amri/DiPlay/pull/679)).
- While DiPlay retries a failed connection, the connection screen shows a tip that fits the failure and the wireless mode: reset CarPlay Wi‑Fi, check the car hotspot, rejoin the network, check permissions or use a USB data cable. Contributed by @acari-git ([#677](https://github.com/shihabal3amri/DiPlay/pull/677)).
- DiPlay also finds the Bluetooth adapter on head units where Android's Bluetooth service returns none. Contributed by @faizannazir ([#641](https://github.com/shihabal3amri/DiPlay/pull/641)).

## Audio, calls and Siri

- On a first setup, confirming the car as DiLink 3.0 or 4.0 sets the navigation audio stream to 14, and DiLink 5.0 to 15, the values the setup guide recommends for BYD head units. A driver who chose a stream keeps it, and re-running the guide never changes a stream left on automatic. [#656](https://github.com/shihabal3amri/DiPlay/pull/656)
- Fix the playback position DiPlay reports to the iPhone for calls, Siri and navigation prompts sent in the 16 kHz audio format. DiPlay counted it at 48 kHz, three times too fast: 14.5 s ahead of the received audio after 20 s of a call in which the driver could not understand the other side, and 7 s ahead for navigation prompts ([#473](https://github.com/shihabal3amri/DiPlay/issues/473), [#536](https://github.com/shihabal3amri/DiPlay/issues/536)). The position now counts at the format's own rate. Music and 48 kHz streams are unchanged. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)

- When the head unit's microphone fails its first read after switching to call mode, DiPlay restarts recording up to three times instead of leaving the call without a microphone. A Seal 05 DM-i (MT6765, Android 9) lost the microphone this way on two of three USB calls ([#647](https://github.com/shihabal3amri/DiPlay/issues/647)). The report logs `Microphone: recording restarted … attempt=N`. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)

- Music no longer underruns every few seconds while the CarPlay screen is in the background. Since 0.2.18, an audio packet the decoder could not take yet waited up to 0.5 s, and a slowed decoder fell further behind: on a DiLink 3.0 the queue grew to 190 packets ([#649](https://github.com/shihabal3amri/DiPlay/issues/649)). Audio now waits at most 0.1 s after draining the decoder once, which still covers the music dropouts fixed in 0.2.18 ([#381](https://github.com/shihabal3amri/DiPlay/issues/381)). Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)

## Display

- Dialogs have a background again on Android 9 and older. Since 0.2.15, those versions drew Settings dialogs such as the car hotspot details without one, over the page behind them ([#640](https://github.com/shihabal3amri/DiPlay/issues/640), [#617](https://github.com/shihabal3amri/DiPlay/issues/617)). [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- On DiLink 4.0 with **CarPlay map on dashboard (experimental)** on, CarPlay no longer restarts after it first connects when the driver touches the screen, as when choosing an app for a route ([#536](https://github.com/shihabal3amri/DiPlay/issues/536)). DiPlay opened the dashboard map before its own window had focus, so a system bar stayed on screen and CarPlay started at 1920×942. The first touch returned focus, hid the bar and restarted CarPlay at 1920×990. DiPlay now opens the dashboard map after its window takes focus, and starts CarPlay when the map is ready, at most 3 s later. The report logs `Cluster activity: launching after the main window took focus`. Pending in-car acceptance. [#663](https://github.com/shihabal3amri/DiPlay/pull/663)
- With the status bar kept on screen, CarPlay no longer stays scaled down after the reversing camera. On an ESSGOO head unit the camera hid the status bar, so DiPlay's window grew from 1280×660 to 1280×720 and DiPlay restarted CarPlay at that size; when the bar came back, the larger picture was fitted into the smaller window ([#643](https://github.com/shihabal3amri/DiPlay/issues/643)). While another window hides the status bar that the driver keeps, DiPlay now keeps the session at its size. The report logs `while another window hides the status bar; keeping CarPlay session`. Pending in-car acceptance. [#674](https://github.com/shihabal3amri/DiPlay/pull/674)
- The swipe-down settings menu inside CarPlay is a centred panel with a dimmed backdrop, a Close button instead of the small X, and **Save and reconnect** kept visible while the settings scroll. **Exit application** stays at the end of the list, away from Save. Contributed by @serein-morii ([#642](https://github.com/shihabal3amri/DiPlay/pull/642)).
- The custom dashboard turn card disappears 5 s after the driver ends navigation. It stayed on the last turn for up to two minutes ([#511](https://github.com/shihabal3amri/DiPlay/issues/511)). After a wireless connection drop, the card is still kept until guidance returns. Pending in-car acceptance. [#644](https://github.com/shihabal3amri/DiPlay/pull/644)

- With **Smooth video** or **Direct video output** on, coming back to DiPlay (from Home or the reversing camera) shows the last CarPlay picture until a new frame arrives, instead of a black screen until the next touch. DiPlay also asks the iPhone for a new picture again. Contributed by @romanchukg-cloud ([#669](https://github.com/shihabal3amri/DiPlay/pull/669)).
- Settings search is a button that expands when tapped, so it no longer squeezes or clips the header buttons on narrow screens or with long translations. Contributed by @bennylee1029 ([#645](https://github.com/shihabal3amri/DiPlay/pull/645)).
- An optional album-artwork card on the dashboard map shows the current song's cover, with title and artist for 8 s after a track change. It is in the dashboard map settings. Contributed by @LuisCav29 ([#660](https://github.com/shihabal3amri/DiPlay/pull/660)).

## Settings backup and reports

- **Settings → Diagnostics → Get the report on a phone** opens the phone page with a **Download report** button, for head units that cannot save or share a file. The report is the one **Save diagnostic report** writes, behind the same random code as the settings backup. Contributed by @Boring206 ([#686](https://github.com/shihabal3amri/DiPlay/pull/686)).
- The phone page can be opened without a camera: the head unit also shows an address such as `192.168.43.1:8888` and a six-digit code to type in a browser. Five wrong codes end code entry until the page is opened again; the QR code keeps working. Contributed by @Boring206 ([#687](https://github.com/shihabal3amri/DiPlay/pull/687)).
- The phone page no longer stalls behind a connection the browser opened but never used: every request waited for it to time out, 10 s. Contributed by @Boring206 ([#685](https://github.com/shihabal3amri/DiPlay/pull/685)).

## Diagnostics

- When DiPlay cannot start the car hotspot, the report says why: the Android request's error, the ADB access state, or that the firmware lists no hotspot start command or rejected it. "This firmware does not support automatic hotspot startup" did not say which, as on an Android 10 DiLink 3.0 with 2023 firmware ([#616](https://github.com/shihabal3amri/DiPlay/issues/616)). [#667](https://github.com/shihabal3amri/DiPlay/pull/667)
- The `Microphone: stats` line records the loudest sample DiPlay sent, as `peakDbfs=…` or `silent`, so a microphone that delivers silence can be told apart from audio the iPhone discards. Playback stats for calls now reach the report: they were dropped by the filter that removes the iPhone's own log lines ([#647](https://github.com/shihabal3amri/DiPlay/issues/647)). [#644](https://github.com/shihabal3amri/DiPlay/pull/644)
- Diagnostic reports log the iPhone's now-playing and route-guidance updates only for the first five, then once per hundred with a count. They were more than half of long reports, and reports cut off by GitHub's size limit lost the lines that mattered ([#473](https://github.com/shihabal3amri/DiPlay/issues/473), [#536](https://github.com/shihabal3amri/DiPlay/issues/536), [#606](https://github.com/shihabal3amri/DiPlay/issues/606)). The per-frame USB multiplexer line in logcat stops after 50 frames ([#634](https://github.com/shihabal3amri/DiPlay/issues/634)). [#644](https://github.com/shihabal3amri/DiPlay/pull/644)

## Updating and reporting problems

Install the official APK over the previous public release to preserve settings and pairing records. The package remains `com.shihab.diplay`; release packaging verifies the existing signing certificate. Source builds omit runtime authentication assets by default; see [building from source](BUILD.md).

Reproduce remaining problems on **0.2.19**, then open **Settings → Diagnostics → Save diagnostic report**. Android 10+ normally saves to **Downloads/DiPlay**; on Android 7.1–9, DiPlay asks for storage access and saves there too. If it is unavailable, follow the save confirmation and use **View report** or **Share**. Review the `.txt` and attach it to a matching [existing issue](https://github.com/shihabal3amri/DiPlay/issues) or [new issue](https://github.com/shihabal3amri/DiPlay/issues/new/choose). Connection reports require the diagnostic log. Reports are not uploaded automatically.

Include car/head unit, Android/DiLink and full firmware, iPhone/iOS, USB or wireless mode, relevant settings, reproduction steps and failure time.

See [validation](VALIDATION.md) for automated checks. No new maintainer vehicle test of the complete release is claimed. The wired startup and USB permission changes, the call, Siri and music audio fixes, the dashboard map and reversing-camera fixes, the phone page and the experimental options above need current in-car feedback; test optional features while parked.

Thanks to the contributors linked in the 23 pull requests above, and to the users supplying diagnostic reports and vehicle feedback.
